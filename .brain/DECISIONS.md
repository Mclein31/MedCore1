## 2026-11-18: dependency audit gate
- [DECISION] **The CI audit gate checks what the server and web ship.** `scripts/audit-prod.mjs` fails on a high/critical advisory only for packages in the production graph of `@medcore/api`, `@medcore/web` and `@medcore/domain` (`npm ls --omit=dev --all`). Advisories on packages that only mobile or dev tooling install are printed, not failed. If npm's output can't be read, or the production set comes back empty, the gate fails. Why: `npm audit --omit=dev -w` decides "dev only" for the whole monorepo, so mobile's React Native tooling made `picomatch` (no patched release exists) fail the server/web gate. Chosen by the owner over a dated allowlist and over a red CI. The mobile audit stays report-only, as before.

## 2026-11-16: demo polish
- [DECISION] **Trapped Capital canonical definition:** Trapped Capital is the sum of unpaid remaining patient balances (`ledger.balanceCents` / `remainingBalance`) on active encounters in `HMO_FINAL_LOA` or `PENDING_SETTLEMENT`, shared between the API briefing (`executiveBriefingService`) and the dashboard scorecard (`computeMacroKpiMetrics`) through `sumTrappedCapitalCents` in `@medcore/domain` (`packages/domain/src/discharge.ts`). Chosen over the older RCM tile formula (`stage !== 'CLEARED_GATE_PASS'` summing `waterfall.netPatientDue`) because: (1) `briefingPrompts.ts`, `ExecutiveAiBriefingCard`, and `MEDCORE_SCRIPT_FINAL.md` explicitly define Trapped Capital as high-balance accounts stuck at final LOA or settlement; (2) per `ONTOLOGY.md` and `DOMAIN/hospital_billing.md`, `ADMITTED` patients have not been cleared MGH and total open receivables across all stages are already reported separately as "Patient receivables" / "Inpatient Receivables"; and (3) per TDR-008 and v2's `settlementPosition`, `balanceCents` reflects actual unsettled exposure after partial payments and RA 9439 promissory financing, whereas v2 `netPatientDue` does not decrement on payment.
- [DECISION] **Cora ledger grounding, automatic retry, and deterministic summary fallback:** `coraService` passes structured `authoritativeLedger` data (charges, statutory/PhilHealth/HMO deductions, `patientResponsibilityBreakdown` including `coverageShortfall`, payments, promissory installments, and disputes) formatted with `₱` strings, and validates every non-notice reply with `findUngroundedPesoAmounts`. When ungrounded peso figures appear, Cora runs one automatic correction retry listing the allowed ledger figures; if the retry stays ungrounded or fails, `coraService` returns `buildDeterministicLedgerSummary` (`modelUsed: 'ledger-summary-fallback'`, clearly labelled and built solely from recorded ledger data, never cached in `aiResultCache`) instead of surfacing an error during patient or demo use. Amends the 2026-10-28 one-call rule for ungrounded-peso recovery only, and relies strictly on live ledger facts rather than invented/mocked answers.
- [DECISION] **Staff AI rate limit (`staff-ai`):** All `/api/v1/staff/ai/*` routes share a single Postgres-backed bucket (`LIMITS.staffAi`, 60 requests per 600 s keyed by `staff.id` in `rate_limit_buckets`), mirroring `patientAiCora`/`patientAiOcr` so shared hospital/venue IPs never lock out other staff while capping runaway Gemini usage.
- [DECISION] **M5 public health check verified:** v2 `GET /api/health` returning only `{ status, database: 'ok' | 'error' }` (`503` on failure) with facility/operational details moved behind authenticated routes is the intended 2026-10-16 audit fix (`M5`).

## 2026-10-16: v2 rebuild (branch `rebuild/medcore-v2`, merged into `main` 2026-10-17)
- [DECISION] Both apps use the original v1 UI over the v2 API through a client-side v1→v2 bridge; the dashboard keeps the v2 staff login (MFA). Client adapters convert pesos/centavos and use server-authoritative sessions, permissions and financial records. Missing API features show unavailable states; no v1 login, demo personas, role switching or invented results. (2026-10-17)
- [DECISION] MedCore is rebuilt from scratch on branch `rebuild/medcore-v2` as an npm-workspaces monorepo: `packages/domain` (pure rules), `apps/api` (Hono + Drizzle + Postgres, Node and Workers entries), `apps/web` (React 19 + Vite + Tailwind 4; staff dashboard only). The old `apps/server`, `apps/dashboard`, `apps/shared`, `apps/mobile` and `scripts/` are removed from that branch only; `main` keeps them (status 2026-11-15: the branch was merged on 2026-10-17, so `main` now has only the v2 layout; v1 survives in git history and on old branches). Implements the whole 2026-10-16 audit by design rather than as patches.
- [DECISION] The web app is the hospital staff dashboard only; there is no patient web portal (removed 2026-10-16 at the owner's request). Patients and families use the mobile app, which calls `/api/v1/auth/patient/*` and `/api/v1/patient/*` with a bearer token. The bill-ready email tells patients to open the MedCore app.
- [DECISION] Money is integer centavos everywhere (bigint columns, `*Cents` JSON fields). A DB CHECK enforces the waterfall identity on every ledger row. Patient-only amounts (exclusions, room upgrade, excess PF) receive the senior/PWD discount pro rata, so a senior with excluded items no longer throws (supersedes the old "non-covered exceeds base" error).
- [DECISION] Patients are a separate principal (`patient_accounts` + `patient_account_links`), never a staff role. Sign-in is only the emailed 6-digit code (MRN + date of birth to register; code goes to `patients.email`). No patient passwords.
- [DECISION] Staff MFA (TOTP + 10 recovery codes) is mandatory and cannot be disabled in production; accounts are created only by emailed invitation (the same link is the admin password reset).
- [DECISION] Exit-pass PIN is 6 digits derived by HMAC from `GATE_PASS_SECRET` and the pass id, never stored; 5 wrong PINs void the pass; signature is checked before the PIN.
- [DECISION] Rate limits live in Postgres (`rate_limit_buckets`), not Workers bindings, so they hold across regions and on Node.
- [DECISION] Official receipt, bill, claim, note and encounter numbers are gap-free per facility and year (`document_counters`); claim and note numbers are unique per facility (a global unique index was a multi-tenant bug caught by tests).
- [DECISION] Online patient payment is `PATIENT_ONLINE_PAYMENTS=disabled|simulated` (default disabled); simulated payments are flagged `is_simulated` and shown as such to staff only.
- [DECISION] AI features (Cora, card OCR, claims preflight scrubber, HMO appeal drafter, executive briefing) are ported onto `@medcore/api` under `/api/v1/staff/ai/*` and `/api/v1/patient/ai/*` with RA 10173 PHI scrubbing, Postgres-backed rate limits (`ai-staff`, `ai-cora`, `ai-ocr`; status 2026-11-16: code has per-patient `patient-ai-cora` / `patient-ai-ocr` at 30 per 10 min and per-staff `staff-ai` at 60 per 10 min across `/api/v1/staff/ai/*`), in-memory deduplicated TTL cache (`aiResultCache`), and audit logging. Supersedes the earlier "AI features are not in v2 yet" note. (2026-10-17)
- [DECISION] The v2 mobile app (`apps/mobile`) keeps its session only as a bearer token in expo-secure-store (this device only, unlocked only); never AsyncStorage (lint-enforced). It validates forms with the same `@medcore/domain` contracts as the API, and the API client copies only whitelisted payment fields so no full card number can ever be sent.
- [DECISION] The staff console and patient portal use the shield badge (`apps/mobile/assets/brand/MedCore_Badge_Logo.png`) as the logo and favicon, matching the mobile app.

## Carried forward from the v1 era (still in force)
Copied verbatim from the archived periods because they still bind the v2 code or the product. Full v1-era history (UI, print, table, token and v1 backend decisions): [archive/DECISIONS_ARCHIVE.md](archive/DECISIONS_ARCHIVE.md).

### Product scope and positioning (Sep–early Oct)
- [DECISION] Strategic scope: MedCore is not an HIS or EMR. It is the financial intelligence and multi-payer reconciliation middleware between hospital systems, payers (PhilHealth, HMOs) and patients.
- [DECISION] MedCore performance target: discharge clearance from 4–8+ hours to under 45 minutes (target under 30 for fully digital settlement).
- [DECISION] Olive AI anti-pattern: no brittle screen-scraping bots and no black-box generative AI for billing math. Use CDC read-replicas, standard APIs and webhooks, and deterministic auditable engines with centavo precision.
- [DECISION] Retain SPC abolition (PhilHealth Circulars 2024-0021 and 2025-0015) as an informational audit flag and retroactive refiling generator.
- [DECISION] Commercial scope guardrails: one facility now, multi-tenancy later; PGC Digital Innovation Challenge (presentation 2026-12-10, Capitol, Tuguegarao) with EGAY and GAD/HGDG alignment (Box 13 Health, Box 19 ICT, target score 15.0 or more).
- [DECISION] Blue Ocean positioning: MedCore sits in the high patient-UX, deep multi-payer inpatient adjudication quadrant, apart from outpatient/telehealth apps, legacy hospital ERPs and B2B HMO switches.

### AI (2026-10-09 to 2026-10-28)
- [DECISION] AI architecture: all AI goes through Hono `/api/v1/ai/*`; clients never call Google directly; `GEMINI_API_KEY` is a Worker secret only. The backend masks PHI (RA 10173) before prompts and injects chart context itself. Deterministic engines own every peso amount; models never calculate, sum or mutate money. Pro-tier and 20-RPD models prohibited. Product design (Cora, claims scrubber, HMO appeal drafter, executive briefing, OCR scanner) is ADR-008 in `MedCore_Vault/DECISIONS/product_decisions.md`.
- [DECISION] AI models: primary `gemini-3.1-flash-lite` (swapped 2026-10-28: ~2 s vs 7–29 s for 3.5 on the free tier), automatic failover to `gemini-3.5-flash-lite` on 429 or transient failure (free tier 15 RPM, 500 RPD each). Pro and 20-RPD models are excluded. Calls go through the Gemini Interactions API (`generateContent` is closed to this account, 2026-10-27) with `store: false` and `response_format` JSON Schema; the Worker runs at `gcp:asia-southeast1`, next to Neon Singapore; 15 s timeout, fast-fail on permanent 4xx. A model that times out, returns 429 or 5xx is skipped for 60 s per isolate (2026-10-28).
- [DECISION] Cora makes one Gemini call per answer (2026-10-28, owner's choice). The separate scope classifier and language-review pass were removed because the free tier took 18–21 s per call and Cora timed out. The answer prompt enforces scope and language itself; the instant keyword guard (`obviousRestrictedRequest`) still blocks prompt-injection and other-patient requests without calling Gemini. Trade-off: a reply in the wrong language is no longer re-checked.
- [DECISION] Cora language contract: `en`, Tagalog `tl`, Taglish `fil`, Ilokano `ilo`. The selected style overrides question, history and record language. Each draft gets an independent language check and at most one regeneration (shared 40 s budget); failure returns an error, never a wrong-language draft. Mobile preference is shared across Cora windows per verified account, not persisted across cold restart. Typing indicator is three pulsing dots. **Status note (2026-11-15):** Partly superseded by the one-call Cora decision (2026-10-28): the separate language check and regeneration were removed; the language contract itself still applies.
- [DECISION] Cora is UI-welcomed only on the first manual open. "Explain My Bill" sends a real question in `WHY_DO_I_OWE` mode and skips the welcome. A semantic topic gate (fail closed) sees only scrubbed user text. Unrelated, other-patient, prompt-extraction and treatment or dosing requests are refused with labeled notices. Unavailable facts return `UNSUPPORTED`. Input cap 2,000 chars, history 8 turns and 8,000 chars, system-role history rejected. Cora is read-only; staff cannot call it. No gate PIN, QR, full member credentials or payment authorization codes enter the context. **Status note (2026-11-15):** Partly superseded: the separate semantic topic gate was removed by the one-call Cora decision (2026-10-28); the answer prompt plus the instant keyword guard enforce scope.
- [DECISION] Runtime AI mocks and canned fallbacks are removed everywhere. Missing credentials, exhausted models, malformed JSON or failed validation return explicit errors. Supersedes the Oct 10 "offline mock fallback" invariant and the Oct 11 chart-aware mock engine. Tests inject provider transport only inside the test suite.
- [DECISION] RTH risk score is an application heuristic: 4% baseline plus deduplicated finding penalties, capped at 99%, review threshold 15%. It is not a validated probability or a statutory threshold. Score, readiness, tier and formula are normalized together and persisted on the claim. Stale chart snapshots are rejected before persistence.
- [DECISION] Appeals use the selected encounter's real diagnosis, physician, disputed charge and facility. No fabricated defaults. The whole final prompt is scrubbed before transmission.
- [DECISION] All five AI features use the private Postgres `ai_result_cache` (migration 0004). TTL 5 min for Cora, briefing and OCR; 30 min for audits and appeals. Exact SHA-256 keys cover account, facility, encounter, authorized inputs, models, prompt, schema, policy and generation revision (bump `CACHE_REVISION` for normalization changes). Short Postgres leases deduplicate across Workers, fail closed on cache outage, and cache only validated successes. Authorization and current chart reads come before cache access. Missing MGH timestamps stay empty in XML. `X-AI-Cache` reports HIT/SHARED/GENERATED/REFRESHED. Results capped at 256 KiB. **Status note (2026-11-15):** Superseded in v2 by the in-memory deduplicated TTL cache (`aiResultCache`, see v2 AI decision above); there is no `ai_result_cache` table in the v2 schema.
- [DECISION] Cora uses the original transparent teal mascot (`apps/mobile/assets/brand/cora-mascot.png`, `ASSETS.brand.cora`, `coraBlink`). Home entry is a 64px mascot in an 80px accessible button, with no visible label. Motion pauses for reduced motion, inactive Home, open chat and background. React Native Web needs explicit image dimensions.

### Networking, payments and SMS
- [DECISION] Per-IP rate limits are network-wide abuse ceilings, never per-person limits: many users share one public IP (hospital, venue Wi-Fi, carrier NAT). Brute-force protection comes from per-account and per-challenge limits. No session or account is bound to an IP, network or device. The mobile app defaults to the hosted Worker so any phone on any network works. (2026-10-28)
- [DECISION] The university presentation requirement overrides any real-gateway gate: GCash, Maya, Visa/Mastercard and BPI/BDO share `apps/server/src/services/simulatedPaymentService.ts` in local and hosted builds. No real gateway, merchant credentials or money transfer. Internal `isSimulatedDemo` stays; patient screens show no simulation banners. QR Ph and promissory rules are separate. PAN, CVV and expiry never reach the API or retry storage (brand and last four only). Patient simulated settlement is rejected in production; hosted full settlement needs the pass-signing secret. **Status note (2026-11-15):** In v2 the switch is `PATIENT_ONLINE_PAYMENTS=disabled|simulated` (see v2 decision above); the v1 file path no longer exists.
- [DECISION] SMS is unconditionally a free sandbox ("completely free and sandbox only" overrides the live-gateway prompt). No provider SDK, endpoint, fetch or live switch; Semaphore/Twilio keys are ignored. Results are `SIMULATED`, provider `SIMULATOR`, reference `SMS-SIM-XXXXXX`. Allowlisted templates reject URLs, unmasked PINs and clinical codes. Dispatch, timeline entry and audit commit atomically; `sms_dispatches` persists history (reads max 100). Billing finalize and send share one billing-ready simulation; one clearance notice per gate pass; SMS errors never reverse committed financial actions. `npm run test:api` rebuilds only a strictly named local `medcore_sms_validation` fixture. Setup: `npm run db:sms`. **Status note (2026-11-15):** v1 implementation details (`sms_dispatches`, `npm run db:sms`) are archived; v2 keeps a simulated SMS outbox (`/api/v1/staff/notifications/sms-outbox`).
