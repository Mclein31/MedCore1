## 2026-10-16: v2 rebuild (branch `rebuild/medcore-v2`)
- [DECISION] MedCore is rebuilt from scratch on branch `rebuild/medcore-v2` as an npm-workspaces monorepo: `packages/domain` (pure rules), `apps/api` (Hono + Drizzle + Postgres, Node and Workers entries), `apps/web` (React 19 + Vite + Tailwind 4; staff dashboard only). The old `apps/server`, `apps/dashboard`, `apps/shared`, `apps/mobile` and `scripts/` are removed from that branch only; `main` keeps them. Implements the whole 2026-10-16 audit by design rather than as patches.
- [DECISION] The web app is the hospital staff dashboard only; there is no patient web portal (removed 2026-10-16 at the owner's request). Patients and families use the mobile app, which calls `/api/v1/auth/patient/*` and `/api/v1/patient/*` with a bearer token. The bill-ready email tells patients to open the MedCore app.
- [DECISION] Money is integer centavos everywhere (bigint columns, `*Cents` JSON fields). A DB CHECK enforces the waterfall identity on every ledger row. Patient-only amounts (exclusions, room upgrade, excess PF) receive the senior/PWD discount pro rata, so a senior with excluded items no longer throws (supersedes the old "non-covered exceeds base" error).
- [DECISION] Patients are a separate principal (`patient_accounts` + `patient_account_links`), never a staff role. Sign-in is only the emailed 6-digit code (MRN + date of birth to register; code goes to `patients.email`). No patient passwords.
- [DECISION] Staff MFA (TOTP + 10 recovery codes) is mandatory and cannot be disabled in production; accounts are created only by emailed invitation (the same link is the admin password reset).
- [DECISION] Exit-pass PIN is 6 digits derived by HMAC from `GATE_PASS_SECRET` and the pass id, never stored; 5 wrong PINs void the pass; signature is checked before the PIN.
- [DECISION] Rate limits live in Postgres (`rate_limit_buckets`), not Workers bindings, so they hold across regions and on Node.
- [DECISION] Official receipt, bill, claim, note and encounter numbers are gap-free per facility and year (`document_counters`); claim and note numbers are unique per facility (a global unique index was a multi-tenant bug caught by tests).
- [DECISION] Online patient payment is `PATIENT_ONLINE_PAYMENTS=disabled|simulated` (default disabled); simulated payments are flagged `is_simulated` and shown as such to staff only.
- [DECISION] AI features (Cora, OCR, claims scrubber, appeals, briefing) are not in v2 yet; they are follow-ups on top of the v2 API.
- [DECISION] The v2 mobile app (`apps/mobile`) keeps its session only as a bearer token in expo-secure-store (this device only, unlocked only); never AsyncStorage (lint-enforced). It validates forms with the same `@medcore/domain` contracts as the API, and the API client copies only whitelisted payment fields so no full card number can ever be sent.
- [DECISION] The staff console and patient portal use the shield badge (`logo/MedCore_Badge_Logo.png`) as the logo and favicon, matching the mobile app.

## Sep–early Oct: Architecture, backend and API
- [DECISION] Strategic scope: MedCore is not an HIS or EMR. It is the financial intelligence and multi-payer reconciliation middleware between hospital systems, payers (PhilHealth, HMOs) and patients.
- [DECISION] One 10-step financial pipeline in `src/utils/financing.ts` and the waterfall engine `waterfall.ts`: Gross → 12% VAT exemption → 20% SC/PWD discount → PhilHealth ACR → HMO LOA → patient due; promissory notes are 0% interest (RA 9439) over 3/6/12 months, centavo-exact. See `ARCHITECTURE.md`.
- [DECISION] MedCore performance target: discharge clearance from 4–8+ hours to under 45 minutes (target under 30 for fully digital settlement).
- [DECISION] Retain SPC abolition (PhilHealth Circulars 2024-0021 and 2025-0015) as an informational audit flag and retroactive refiling generator.
- [DECISION] Olive AI anti-pattern: no brittle screen-scraping bots and no black-box generative AI for billing math. Use CDC read-replicas, standard APIs and webhooks, and deterministic auditable engines with centavo precision.
- [DECISION] Five-pillar engine (GUIDE → VERIFY → REWARD → REPORT → IMPROVE) is internal middleware only. It is not shown in navigation, and "Reward" terminology is removed from the UI.
- [DECISION] Platform identity is AQROMED (formerly MedCore). Stack: PostgreSQL 16+ via Drizzle ORM (`server/db/schema.ts`), Hono API on Cloudflare Workers via Hyperdrive, plain-light-mode React dashboard.
- [DECISION] Client separation: the dashboard is the hospital Command Center only. The in-dashboard phone simulator and Patient Clarify preview are removed. The mobile app is a separate Expo client on the shared backend (the old "future native mobile" status is superseded). API client is modular `src/api/*`; the `services/apiClient.ts` facade is deleted.
- [DECISION] Auth: PBKDF2 users, 32-byte session tokens with an 8-hour shift lifespan. Both `Authorization: Bearer` and HTTP-only cookies are accepted. Password is mandatory with no fallback seed password. `X-Demo-Role` override only in non-production.
- [DECISION] Seeder safeguard: `scripts/seedPostgres.ts` aborts on any non-localhost `DATABASE_URL` unless `--force` or `FORCE_SEED=true`. Seed accounts use the shared password from `SEED_PASSWORD` (never write the value in notes).
- [DECISION] Payments: `payments.idempotency_key` is `varchar(128)` (alphanumeric references such as `TXN-DEMO-QRPH-*`), keys over 128 chars return 400 `INVALID_IDEMPOTENCY_KEY`. Settlement is one `db.transaction()` (payment, BIR receipt, gate pass and bed release when fully settled, encounter and waterfall, timeline, audit); a `23505` race returns the cached result. One payment equals one receipt.
- [DECISION] All clearance and settlement transitions (cashier, RA 9439 promissory note, supervisory waiver) run inside `db.transaction()`. Encounter create and delete are transactional. A chargemaster item with a dispute cannot be deleted (`onDelete: restrict`). Waiver audit rows use `user.facilityId`. Gate-pass re-verify is idempotent and keeps the original `verifiedAt`.
- [DECISION] Canonical `recalculateAndPersistWaterfall` (`server/services/waterfallPersistence.ts`) is the only server waterfall persistence path. Chargemaster `qty`, `unitPrice` and `grossAmount` stay in sync end to end. Philippine eSOA and BIR Official Receipt model: `GET /encounters/:id/statement` (alias `/invoice`).
- [DECISION] Local runtime is `server/standalone.ts` (`@hono/node-server`, port 8787) with `npm run dev` running server and client via `concurrently`. `/api/health` runs a live Postgres query. `.wrangler/` is git-ignored.
- [DECISION] Encounters list is one base join plus batched child queries (no N+1), with `search`, `status`, `stage` and `hmo` filters. PhilHealth eSOA XML comes from the backend (`claimsApi.getPhilhealthEsoaXml`) with a deterministic client fallback only when the server is offline.
- [DECISION] Demo accounts use official `UserRole` enums (`HMO_COORDINATOR`, `CLAIMS_ENCODER`, `LOBBY_SECURITY`, and so on). Facility `SJMC-MNL` is the documented single-facility default.
- [DECISION] Repository is feature-sliced with `@/*` path aliases and barrel exports (`src/features/*`, `src/components/modals`, `src/hooks`, `src/pages`). Light mode only: no `dark:` classes and no `darkMode` in Tailwind config.
- [DECISION] Tailwind token scale: z (`60`–`100`, `modal` 1000, `popover` 2000, `toast` 3000, `tooltip` 4000, `confirmation` 9999), `backdrop-blur-2xs/xs`, `shadow-2xs/xs`. Use `focus:outline-none`.
- [DECISION] Confirmations: one centralized `ConfirmationModal` via `requestConfirmation(options)` in `MedCoreContext`, rendered by `createPortal` into `document.body` at `z-confirmation`, with body scroll lock, focus trap, Escape cancel and double-execution lock. Typed keyword friction (`OVERRIDE`, `RELEASE`, `CONFIRM`) for statutory overrides and bed release. Routine actions are blue, destructive red; dashboard button variant equals modal confirm variant (Waive = danger, Approve and Finalize = primary, Sign As Declared = warning).
- [DECISION] Print engine: isolated `#medcore-print-root` bus with seven statutory templates (eSOA, gate pass with QR and HMAC, BIR OR, executive report, discharge dossier, coverage report, claims audit), full printable width, repeated table headers, no row splits.
- [DECISION] Gate-pass PIN is shown identically on screen and print, and lobby verification persists as `VERIFIED_AT_LOBBY` with `verifiedAt` (later superseded by the keyed random-PIN design in the Oct 9 entry).
- [DECISION] Supervisors may waive contested items in place from `WhyDoIOweThisDrawer` under RA 9439 goodwill protocols. Waived and resolved states (`SUPERVISORY_WAIVED`, `WAIVED`, `SUPERVISOR_WAIVED`, `HMO_RECONSIDERED`, `RESOLVED`) leave active queues and decrement badges.
