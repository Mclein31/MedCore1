# AQROMED / MedCore: Architecture (Operational Brain)

> Describes the v2 code on `main` (verified against the repository 2026-11-15). The v1 architecture (`apps/server`, `apps/dashboard`, `apps/shared`, `scripts/`) is preserved in [archive/ARCHITECTURE_V1_ARCHIVE.md](archive/ARCHITECTURE_V1_ARCHIVE.md). Setup and commands: root `README.md`, `DEPLOY.md`, `TESTING_GUIDE.md`.

## 1. Stack and topology
- **Monorepo** (npm workspaces, root `package.json` v2.0.0, Node 22.13+ / 24.3+ / 26+): `packages/domain` (pure business rules, no I/O), `packages/icons` (`@medcore/icons`, Solar geometry, CC BY 4.0), `apps/api`, `apps/web`, `apps/mobile`. Root `overrides` pin React/ReactDOM to 19.3.0 so both apps and the native renderer share one runtime.
- **API (`apps/api`, `@medcore/api`):** Hono + Drizzle ORM + PostgreSQL + Zod. Two entries: `src/node.ts` (local, port 8787) and `src/worker.ts` (Cloudflare Workers). Worker `medcore-backend` → `https://medcore-backend.mcleinonza0531.workers.dev`, config `apps/api/wrangler.jsonc` (`nodejs_compat`, `placement.region: gcp:asia-southeast1`, hourly cron `17 * * * *` for retention purge, observability on). Deploy: `npm run deploy -w @medcore/api`.
- **Database:** Neon Postgres 17, project `medcore-sg` (`aws-ap-southeast-1`, Singapore). Branch `production` = schema only; branch `demo` = fictional data, used by the hosted Worker. Reached via Hyperdrive `HYPERDRIVE` (`b611eac58efa4966b649dfa7d1631b2a`, direct endpoint, caching disabled). Warm latency about 435–463 ms, cold start about 1.8 s (measured 2026-10-16). Ohio project retired 2026-10-16, kept only as rollback until deleted.
- **Dashboard (`apps/web`, `@medcore/web`):** React 19.3 + Vite 8 + Tailwind 4, staff only. Hosted on Vercel `https://med-core1.vercel.app` (also `medcore1.vercel.app` in `ALLOWED_ORIGINS`). Root `vercel.json` builds `apps/web/dist`, rewrites `/api/:path*` to the Worker before the SPA fallback (same-origin cookies), and sets CSP/HSTS headers.
- **Mobile (`apps/mobile`, `@medcore/mobile`):** Expo SDK 58 / React Native 0.88 / React 19.3 patient app. Defaults to the hosted Worker unless `EXPO_PUBLIC_API_BASE_URL` is set. `ios/` and `android/` are generated (`npm run native:prebuild`) and git-ignored; native config in `app.json` and `apps/mobile/plugins/` (`withoutPushEntitlement.js`). Release builds embed the bundle and require an HTTPS API.
- **AI:** Google Gemini via the Interactions API, always server-side. Worker vars: `GEMINI_MODEL` = `gemini-3.1-flash-lite`, `GEMINI_BACKUP_MODEL` = `gemini-3.5-flash-lite`, `GEMINI_PRO_MODEL` = `gemini-3.1-flash-lite`.
- **Email:** dependency-free SMTP mailer (Gmail App Password, sender `medcore1.noreply@gmail.com`), `MAIL_TRANSPORT=smtp`.
- **Not in v2:** no R2 binding (v1 used bucket `aqromed-documents`; `medrec-vault` belongs to another project), no `neon.ts` / `@neon/*` tooling, no real payment gateway, no real SMS provider.

## 2. Domain engine (`packages/domain/src`)
- Modules: `money.ts`, `waterfall.ts`, `promissory.ts`, `discharge.ts`, `access.ts`, `contracts.ts`, `governmentId.ts`, `password.ts`, `dates.ts`.
- Legal deduction order (RA 9994, 10754, 11223; DOH/BIR): `Gross → 12% VAT exemption → 20% SC/PWD discount → PhilHealth case rate → HMO LOA within MBL → Net patient due`. Identity: Gross ≡ VAT + SC/PWD + PhilHealth + HMO + Net patient due, enforced by a DB CHECK on every ledger row.
- Money is integer centavos everywhere (bigint columns, `*Cents` JSON fields). Promissory notes are 0% interest (RA 9439) over 3/6/12 months.
- Models never compute money; deterministic engines inject read-only figures into prompts.

## 3. Discharge flow (`discharge.ts`)
Stages: `ADMITTED` → `MGH_DECLARED` → `DOCTOR_PF_PENDING` → `PHARMACY_RTS_AUDIT` → `HMO_FINAL_LOA` → `PENDING_SETTLEMENT` → `CLEARED`, as a strict state machine (actions `DECLARE_MGH`, `START_CLEARANCE`, `SIGN_PROFESSIONAL_FEE`, `CLEAR_PHARMACY`, `RECORD_FINAL_LOA`, …) with SLA status `ON_TRACK | WARNING | BREACH`. Doctor PF timeout is persisted (migration `0002_doctor_pf_timeout`). Settlement (payment, full promissory arrangement or zero copay) clears the encounter and issues an exit pass: HMAC-signed, 6-digit PIN derived from `GATE_PASS_SECRET` + pass id (never stored), five wrong PINs void the pass, verified at `/api/v1/staff/gate-passes/verify`.

## 4. Data model (`apps/api/src/db/schema.ts`)
`facilities`, `staff_users`, `staff_recovery_codes`, `auth_challenges`, `patients`, `patient_accounts`, `patient_account_links`, `login_codes`, `sessions`, `rate_limit_buckets`, `document_counters`, `beds`, `encounters`, `charges`, `philhealth_claims`, `hmo_coverages`, `ledgers`, `payments`, `receipts`, `promissory_notes`, `gate_passes`, `disputes`, `timeline_events`, `audit_logs`, `staff_notification_reads`.
- Migrations in `apps/api/drizzle/`: `0000_init`, `0001_hardening` (immutability/no-delete triggers), `0002_doctor_pf_timeout`, `0003_notification_reads`. Run with `npm run db:migrate` (`src/db/migrate.ts`). On hosted `demo`, only `0000`–`0001` are recorded; `0002`–`0003` await the owner (TODO).
- All FKs RESTRICT; triggers make payments, receipts, signed note terms and the audit log immutable. Sensitive columns (PhilHealth PINs, phones, discount IDs, borrower IDs, MFA secrets) are AES-256-GCM encrypted with `DATA_ENCRYPTION_KEY`, bound to row and column. Receipt, bill, claim, note and encounter numbers are gap-free per facility and year (`document_counters`).
- Seed (`npm run db:seed`, `src/db/seed.ts`): fictional facility `SJMC-MNL` (St Jude), staff `*@stjude.example.test` with `SEED_PASSWORD`. `npm run db:shift-demo-dates` re-dates activity tables only (audit log untouched).

## 5. API surface (`apps/api/src/app.ts`)
`/api/health`, `/api/v1/auth/staff/*` (password + TOTP, invitations, recovery codes), `/api/v1/auth/patient/*` (MRN + DOB link, 6-digit email code), `/api/v1/staff/encounters/*`, `/api/v1/staff/users/*` (administration), `/api/v1/staff/directory`, `/api/v1/staff/ai/*`, `/api/v1/staff/*` operations (notifications, SMS outbox, facility SLA, promissory installments, gate-pass verify), `/api/v1/patient/*` (stays, bill, coverage, payments, disputes, plans, pass), `/api/v1/patient/ai/*` (Cora, OCR).
- Staff roles (`access.ts`): `HOSPITAL_CFO`, `BILLING_SPECIALIST`, `CLAIMS_ENCODER`, `HMO_COORDINATOR`, `ATTENDING_PHYSICIAN` (own patients only), `LOBBY_SECURITY` (verify passes only). One permission matrix; waivers have separation of duties and a ₱5,000 limit below the CFO. Patients are a separate principal and can never hold staff permissions.
- Security middleware (`middleware/http.ts`, `services/sessions.ts`, `services/rateLimit.ts`): opaque 256-bit sessions stored as SHA-256 (staff 8 h absolute / 30 min idle; patient 30 d / 7 d idle); `__Host-`, HttpOnly, Secure, `SameSite=Strict` cookies for staff, bearer tokens for mobile; CSRF header `x-medcore-csrf: 1` + Origin allowlist + Fetch Metadata on cookie writes; client IP from `cf-connecting-ip` on Workers; Postgres-backed rate limits (per-IP ceilings are network-wide, per-account limits do brute-force protection; per-patient Cora/OCR 30 per 10 min); 64 KB body cap; append-only `audit_logs`.

## 6. Dashboard structure (`apps/web/src`)
`router.tsx`, `staff/` (v2 staff sign-in, invitations, MFA/account, staff administration, audit log), `v1/` (the original v1 Command Center UI running over the v2 API through a client bridge: Home, Discharge Clearance, Encounters & Ledgers, Approvals & Disputes, Claims & eSOA, RCM Analytics, Settings), `pages/`, `components/`, `lib/`. Pages are code-split with route prefetch; census polling 15 s with background reads (`?refresh=background`).

## 7. Mobile structure (`apps/mobile/src`)
`screens/`, `navigation/`, `components/`, `hooks/`, `services/`, `config/apiConfig.ts`, `lib/` (`v2Bridge.ts` adapter to the v2 API, `sessionToken.ts` / `auth.tsx` session in expo-secure-store, `paymentAttempts.ts`, `gatePassCache.ts`). Patient flows: email-code sign-in, Home, Bill, Coverage, Payments (simulated), payment plan, question a charge, Documents, exit pass QR/PIN, Cora (voice input on native via `expo-speech-recognition`), card OCR. Polling 20 s (unread 30 s, paused in background) behind a 4 s shared read cache. Deep links `medcore://`.

## 8. AI services (`apps/api/src/services/ai/`)
`coraService` (patient billing concierge, en/tl/fil/ilo, one Gemini call per answer), `claimsForensicService` (claims preflight scrubber, RTH heuristic), `hmoAppealService`, `executiveBriefingService`, `ocrService` (benefit cards, government IDs), `phiScrubber` (RA 10173, request-scoped reversible tokens), `aiResultCache` (in-memory deduplicated TTL cache per isolate), `coraScope`, `coraLanguage`, `geminiClient` (Interactions API, `store: false`, JSON Schema output, 15 s timeout, 60 s per-isolate cooldown for a model that times out or returns 429/5xx), `structuredResponse`, `prompts/`.
